# How-to: `bignum_is_prime_standard.json`

## Purpose and lifecycle

This committed source manifest is consumed by the C11 `bench_matrix` tool from benchmark-framework v1.0.0. It is edited by the project owner when a reviewed benchmark scenario changes; generated result files belong under `benchmarks/reports/` and are not source manifests. `schema_version: 1` is the only supported version. Additive fields require a framework compatibility review; removed or renamed fields require a new schema version.

## Schema

The root is an object with required integer `schema_version` and required array `profiles`. Each profile is an object with required string fields `id`, `input_kind`, `operation_kind`, `measure_mode`, `size_profile`, and `capacity_profile`. There are no implicit defaults: every field must be present. `id` is unique within the manifest. The consumer rejects malformed JSON, unsupported schema versions, missing fields, duplicate IDs, and unsupported vocabulary before launching samples.

## Vocabulary

| Field | Allowed values | Meaning |
|---|---|---|
| `input_kind` | `zero`, `nonzero`, `mixed` | Dataset shape generated by the adapter |
| `operation_kind` | `mr-quick`, `mr-standard`, `mr-strong`, `mr-mixed` | One, eight, sixteen, or rotating four-to-twelve Miller–Rabin rounds |
| `measure_mode` | `end-to-end`, `kernel-only` | Include or exclude preparation from the timed interval |
| `size_profile` | `one`, `quarter`, `half`, `variable`, `near-capacity` | Logical bignum word length |
| `capacity_profile` | `normal`, `near-capacity` | Normal or boundary-near storage condition |

## Complete valid example

```json
{
  "schema_version": 1,
  "profiles": [
    {
      "id": "nonzero-one-standard-kernel",
      "input_kind": "nonzero",
      "operation_kind": "mr-standard",
      "measure_mode": "kernel-only",
      "size_profile": "one",
      "capacity_profile": "normal"
    }
  ]
}
```

## How to run

```bash
make bench_matrix CONFIG=release USE_ASM=no \
  REPORT_NAME=c11_standard_smoke \
  BENCH_MATRIX_REPETITIONS=1 \
  BENCH_MATRIX_ITERATIONS=1000 \
  BENCH_MATRIX_MT_TOTAL_ITERATIONS=2000 \
  BENCH_MATRIX_WARMUP=10 \
  BENCH_MATRIX_DATA_COUNT=16
```

The command reads this source manifest and writes `benchmarks/reports/c11_standard_smoke_matrix.json` and its statistics summary. A valid sample contains one `benchmark=...` protocol line before `Benchmark finished.` and exposes elapsed seconds and nanoseconds per call.

## How to modify

Copy an existing profile, assign a unique ID, choose only values from the vocabulary table, validate the JSON with `jq empty`, update this profile table and explain the scenario. Run the C11 and ASM smoke matrices, compare identical profile sets, and review the raw report before accepting a baseline.

## Baseline and failure handling

Baseline comparison requires identical IDs and compatible schema. Missing or extra profile IDs are a failed comparison, not a partial success. Malformed JSON, unsupported schema, missing required fields, duplicate IDs, and invalid vocabulary stop matrix execution before samples are accepted. A nonzero benchmark process or missing protocol marker invalidates that sample and the matrix result.
